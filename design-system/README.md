# FormatDesk · Дизайн-система

Сайт дизайн-системы продукта FormatDesk: общий визуальный язык лендинга и сервиса
(«экран версии» форматного приказа ФНС для операторов ЭДО).
Сценарии и содержание Lo-Fi прототипа релиза 1 сохранены и перенесены в новый визуальный язык.

## Запуск

Сборка не нужна, сайт статический:

```bash
cd /mnt/agents/output/project
python3 -m http.server 8901
# открыть http://localhost:8901/design-system/
```

Сервер запускается из корня `project/`, а не из папки `design-system/`: раздел «Иллюстрации»
ссылается на гравюры лендинга как `../assets/`, и они должны быть доступны серверу.

## Состав

| Путь | Что это |
|---|---|
| `index.html` | Сайт: Главная, Основы, Компоненты, Голос бренда, Экраны продукта (hash-навигация) |
| `tokens.css` | Единственный источник значений — CSS-переменные |
| `tokens.json` | Машинно-читаемая копия токенов |
| `styles.css` | Библиотека компонентов `.fd-*` и стили сайта |
| `assets/` | Фирменная графика: логотип (`logo.svg`, `logo-mark.svg`, `favicon.svg`), спот-иллюстрации пустых состояний (`empty-search.svg`, `empty-archive.svg`, `error-connection.svg`); локальные копии гравюр лендинга (`eng-*.webp`) |
| `app.js` | Интерактив: вкладки, диалог, меню, тосты, форма, пагинация |
| `proto-theme.css` | Тема ДС для Lo-Fi прототипа (переопределения по каскаду, только токены) |
| `screens/prototip/index.html` | Копия Lo-Fi прототипа р1 + подключённая тема. Исходник `/mnt/agents/output/app/prototip/index.html` **не изменён** |

## Происхождение (корпус и референсы)

- Корпус продукта: `/mnt/agents/output/project/` — `MD/PRD.md` (аудитория S1/S2, метрики),
  `MD/AGENTS.md` (границы р1), Lo-Fi прототип `app/src/App.jsx` (сценарии SCR-CAT → SCR-VER → SCR-REQ → SCR-ANC → SCR-SKL).
- Голос бренда: отдельного документа в корпусе нет — принципы собраны из PRD, записей интервью
  и реальных текстов прототипа; база — ясный спокойный язык без канцелярита (указано в ТЗ как default).
- Лендинг: `/mnt/agents/output/app/` — оттуда Cormorant Garamond + Inter, кремовый фон, гравюрный стиль иллюстраций.

## Допущения

- Тёмная тема не делалась: продуктовый контекст — работа с документами в офисе, светлая тема покрывает р1.
- Терракота `#C86A4A` даёт 3.75:1 с белым текстом — для кнопок и текста заведён более тёмный `--fd-accent-strong #A9502F` (≥4.5).
- Выделение строк данных `#F6FFED / #D9F7BE` — зафиксированное ранее решение по прототипу, сохранено как токен.
- Тексты о голосе бренда восстановлены по корпусу; выдуманных исследований и цитат нет.
- Демонстрационные состояния: в прототипе первая загрузка экрана версии намеренно показывает ошибку
  (заложено в исходный Lo-Fi для демонстрации состояния); внешние ссылки ведут на nalog.gov.ru.

## Результаты проверок (2026-11-26, фактически выполнено)

Контраст (WCAG AA, расчёт по относительной яркости):

- Текст `#1A1A1A` на `#F7F4ED` — 15.8; на `#FFFFFF` — 17.4
- Вторичный `#5C5749` на `#F7F4ED` — 6.6; на белом — 7.2
- Белый на primary `#1F3D2E` — 11.9; на primary-hover — 8.6
- Белый на accent-strong `#A9502F` — 5.4; accent-strong на креме — 4.9
- Статусы: success 7.1 · warning 5.3 · error 5.9 (текст на своей подложке)
- Текст на выделении `#F6FFED` — 16.9
- Исключение: неактивный текст `#A39B87` — 2.5 (disabled-элементы освобождены от требования AA — отмечено осознанно)

Интерактив и доступность (Playwright, headless Chromium):

- Диалог: открытие, Esc, клик по фону, возврат фокуса на кнопку, удержание фокуса внутри (Tab-кольцо) — OK
- Меню: клик, стрелки ↑↓, Esc с возвратом фокуса, закрытие кликом снаружи — OK
- Вкладки: стрелки ← →, aria-selected — OK
- Форма: пустое обязательное поле → состояние ошибки с текстом-подсказкой; заполнение → успех — OK
- Тосты: появление, закрытие, aria-live — OK
- prefers-reduced-motion: все переходы отключаются в tokens.css — OK (правило есть; визуально в эмуляции не проверялось)
- Узкое окно 390px: `scrollWidth` = 390 на всех разделах — горизонтальной прокрутки нет; широкое 1364px — OK
- Консоль: ошибок JS нет на всех разделах и в темизированном прототипе — OK
- Прототип в новой теме: каталог → (демо-ошибка → «Повторить») → экран версии → модалка якоря (Esc) → вкладка «Макет» — OK, скриншоты сняты

Логотип, иконки, иллюстрации (2026-11-26, Playwright):

- Раздел «Логотип»: 3 плашки (крем / тёмно-зелёная / белая) и карточка правил — рендер OK
- Раздел «Иконки»: все 17 иконок отображаются, акценты (золото, терракота) на месте — OK
- Раздел «Иллюстрации»: 3 спот-иллюстрации (SVG) и 2 гравюры (`../assets/eng-*.webp`) — рендер OK, HTTP 200
- Пустое состояние в «Компонентах» использует `assets/empty-search.svg` — OK
- Консоль без ошибок, HTTP ≥400 нет; 390px — `scrollWidth` = 390 на «Основах» и «Компонентах», сетки складываются в 1–2 колонки

Не проверялось / осталось демонстрацией:

- Реальные данные: прототип работает на вымышленных значениях (как и исходный Lo-Fi).
- Кнопка «AI-черновик» в переключателях и пагинация — базовый набор за пределами р1, помечены бейджами.
- Проверка скринридером не выполнялась (только разметка aria и клавиатурная навигация).

Отличие версии в репозитории от локальной: `design-system/screens/prototip/index.html`
на GitHub — лёгкая обёртка, которая загружает исходный прототип из корня репозитория
(`/prototip/index.html`, уже опубликован) и подключает в него тему `proto-theme.css`
и шрифты (тот же origin). Локально в этой папке лежит полная копия прототипа
с уже встроенной темой — так папка работает автономно. Содержимое и поведение экранов
в обоих вариантах одинаковые.

Гравюры `eng-*.webp`: на GitHub не дублируются — страница ссылается на них как
`../assets/`, то есть на уже опубликованные файлы лендинга в корне репозитория
(`/assets/`). Локальные копии в `design-system/assets/` нужны только для локального
запуска и предпросмотра; в репозиторий они не попадают.
